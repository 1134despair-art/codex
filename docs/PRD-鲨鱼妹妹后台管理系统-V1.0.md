**文档版本：** V1.0

**基线日期：** 2026-08-14

**适用对象：** 产品、设计、前端、后端、测试、交付与客户演示人员

> 本文档以当前可运行的 `admin-web` 系统为事实基线，并参考《鲨鱼妹妹项目需求-后台管理系统功能列表_V3.2》。系统当前为纯前端 Demo：本地可实现的数据操作必须形成真实业务流；支付、设备远控、物流接口、消息推送、OTA 推送和基础设施能力只做确定性静态模拟，不代表已经接入真实外部系统。

## 1. Summary

鲨鱼妹妹设备运营管理后台用于统一管理海上设备的用户、经销商、项目、库存、固件、售后、物料、支付与权限数据。系统以设备 SN 为关键业务标识，以经销商组织关系和国内/海外数据域控制数据范围，并通过操作日志记录关键变更。

本 PRD 同时作为开发实现说明和测试验收基线。正文定义目标行为；“当前实现差异与待关闭问题”列出的内容不得被视为已验收需求。

## 3. Background

### 3.1 业务背景

设备从平台入库开始，会经历经销商交付、用户绑定、项目使用、固件升级、故障维修、物料发放、换机和售后责任转移。业务参与方多，且国内和海外数据需要隔离。如果只依赖表格或线下沟通，容易出现设备归属不清、审批不可追溯、库存和服务记录不一致等问题。

### 3.2 当前产品形态

- 中文浅色桌面后台，最低支持 1024px 宽度。
- Vue 3 + TypeScript + Element Plus + Pinia + Vue Router。
- 业务数据保存在 `localStorage`，数据库键为 `shark-sister-admin.db.v11`。
- 会话键为 `shark-sister-admin.session.v1`。
- 页面只调用 Service，不直接操作存储。
- 列表接口兼容若依结构，后续可以替换为真实 API。
- 当前包含 24 个登录后菜单页面和登录、首次改密页面。

### 3.3 问题定义

1. 用户、设备、经销商、项目和售后记录需要使用一致的关联数据。
2. 一级和二级经销商只能查看及操作授权范围内的数据。
3. 设备出入库、调货、解绑、换 SN 和售后转移必须同步更新设备归属。
4. 工单、投诉和物料申请需要明确的状态流与处理责任人。
5. 所有高风险操作需要原因、影响对象、结果、通知和审计日志。
6. Demo 必须支持客户完整演示，但不能把静态模拟描述为真实外部调用。

## 4. Objective

### 4.1 产品目标

- 提供从设备入库到售后结束的统一运营视图。
- 让平台、一级经销商和二级经销商在各自数据范围内完成日常工作。
- 让新增、编辑、删除、审批、发货和状态变更在刷新后仍然保留。
- 为未来接入若依后端保留稳定的路由、权限和 Service 边界。
- 为测试人员提供可重复、可恢复、可追踪的演示数据环境。

### 4.2 成功指标

| --- | --- |

## 5. Market Segments

### 5.1 平台管理员

负责全局运营、设备和库存、OTA、支付配置、管理员、角色权限和审计。可以在国内与海外数据域之间切换，但一次只操作当前数据域。

### 5.2 一级经销商管理员

负责自身及下级经销商的项目、设备、库存和售后协作。可以维护自身质保规则、发起或处理授权业务，但不能访问其他一级经销商和平台系统配置。

### 5.3 二级经销商管理员

仅负责自身项目、设备、库存和售后业务。首次登录需要修改密码，不能访问经销商管理、OTA、支付配置和系统管理。

### 5.4 总部售后或自定义角色

由平台在角色权限页配置菜单、动作权限和数据范围。典型职责是处理工单、投诉、物料审批与发货。该角色是否可操作某条记录，还要满足当前处理人或当前审批节点条件。

## 6. Value Propositions

- **设备责任清晰：** 通过 SN、当前归属和归属历史追踪设备责任链。
- **渠道数据隔离：** 组织层级、角色权限和数据域共同限制可见范围。
- **售后流程可追踪：** 分配、回复、审批、发货、换机和转移均保留过程记录。
- **演示结果可信：** Demo 中的 CRUD 和状态流真实更新本地关系数据，不只是弹出成功提示。
- **后续接入成本低：** 页面依赖统一 Service 与若依风格返回结构，可替换为真实后端。

## 7. Solution

### 7.1 范围与非目标

#### 7.1.1 本期范围

- 登录、账号锁定、首次改密、权限刷新和退出。
- 工作台实时统计、待办和快捷入口。
- 用户、经销商、项目、设备、仓储、OTA。
- 报修、留言、投诉、物料、物流、换 SN、售后转移、质保和审批流程。
- 支付订单、支付配置、Banner。
- 管理员、角色权限和操作日志。
- 本地数据迁移、恢复示例数据、导入导出和自动化验收。

#### 7.1.2 非目标

- 不连接真实支付网关、设备控制平台、快递100、短信、邮件或推送服务。
- 不提供真实服务器部署、CDN、消息队列或并发容量证明。
- 不提供完整移动端工作流或暗色主题。
- 不在当前后台实现 App 注册、找回密码和 App 端 Banner 消费逻辑。
- 不将静态 Demo 作为生产级密码加密和安全合规实现。

### 7.3 通用界面与交互要求

#### 7.3.1 框架布局

- 展开侧栏宽 224px，收起侧栏宽 64px，顶栏高 64px。
- 1280px 以下自动收起侧栏；1024px 为最低桌面宽度。
- 业务页面全宽自适应，桌面左右边距 24px，窄屏为 16px。
- 左侧分组支持上下展开、状态记忆和当前路由自动展开。
- 所有业务详情、编辑和高风险确认使用居中弹窗，不使用右侧抽屉。

#### 7.3.2 列表页结构

列表页统一为“标题与主操作、Tab、筛选栏、表格工具栏、表格、分页”。筛选、Tab 数量、排序和分页均基于当前数据实时计算。

#### 7.3.3 表单

- 标签位于控件上方，必填项明确标记。
- 输入框只显示一层边框；错误信息位于控件下方。
- 关联对象使用动态下拉，不允许手工填写任意经销商、账号、设备、快递公司或审批人。
- 业务编号、创建时间、更新时间、固件初始版本和自动状态不得要求用户填写。
- 高风险操作必须填写原因，并展示影响对象和影响说明。

#### 7.3.4 页面状态

- 加载：列表和弹窗显示加载反馈，禁止重复提交。
- 空数据：说明当前条件下无数据，不能伪造记录填充页面。
- 无搜索结果：保留筛选条件并提供重置入口。
- 表单错误：定位到具体字段，不写入部分数据。
- 无权限：显示 403 页面或隐藏无权限操作。
- 成功：关闭弹窗、刷新列表并显示成功反馈。
- 高风险：二次确认、原因必填、写通知和日志。

#### 7.3.5 数据导出

- 除工作台和纯配置预览外，业务列表默认支持导出；导出内容为当前 Tab、人工筛选和关联筛选共同命中的全部记录，不受当前分页限制。
- 导出权限使用独立的 `模块:export` 权限键，可在角色权限树中单独启用或撤回；按钮和 Service 必须同时校验权限。
- 导出遵守当前账号的数据域和组织范围，不得导出越权记录；账号、手机号和邮箱继续脱敏，密码、密钥、图片二进制及权限集合不得进入导出文件。
- 每次导出生成操作日志，记录模块、Tab、导出数量、操作者和时间。

### 7.4 登录与账号安全

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| AUTH-001 | 账号密码登录 | 账号 4-20 位，密码 6-20 位；账号、密码、验证码全部通过后登录 |
| AUTH-002 | 图形验证码 | 四位验证码可刷新，有效期 5 分钟；错误或过期拒绝登录并刷新 |
| AUTH-003 | 失败锁定 | 同一账号连续密码错误 5 次后锁定 30 分钟 |
| AUTH-004 | 登录日志 | 成功、失败、锁定、退出均生成审计日志 |
| AUTH-005 | 首次改密 | `firstLogin=true` 的账号只能进入首次改密页；新密码至少 8 位且两次一致 |
| AUTH-006 | 账号与角色联动 | 管理员或经销商账号被禁用、角色被禁用或权限被撤回后，当前会话刷新并立即生效 |
| AUTH-007 | 路由保护 | 未登录访问业务路由跳转登录；无权限访问显示 403 |

### 7.6 客户与渠道

#### 7.6.1 用户管理

- 用户来源于 App 注册数据，后台不提供新增用户。
- 支持账号、昵称、注册方式、注册时间和账号状态筛选。
- 列表展示用户 ID、脱敏账号、昵称、注册方式、真实绑定设备数、注册时间、最近活跃和状态。
- 详情展示基本信息、真实绑定设备和航点数据；航点按用户 ID 关联查询。
- 只展示用户在 App 选择保存到服务器的航点，并显示来源设备、位置、坐标、上传时间和同步状态；本地未上传航点不进入后台数据库。
- 启禁用与重置密码必须同步 App 用户登录实体，并生成通知和日志。
- 重置后的临时密码由 Demo 固定为 `Reset123!`，下次登录必须改密。

#### 7.6.2 经销商管理

- 支持一级和二级经销商新增、编辑、启禁用、重置密码。
- 二级经销商必须从有效一级经销商中选择上级；一级经销商不得设置上级。
- 新增经销商时同步创建登录账号和组织 ID，首次登录必须改密。
- 管理设备数从设备归属实时计算，不保存独立展示值作为事实来源。
- 详情包含设备范围、售后服务和关联账号。
- 一级经销商只能维护自身及下级经销商。

#### 7.6.3 项目管理

- 项目由业务数据产生，后台不提供新增入口。
- 支持船名、设备 SN、船东、所属经销商和创建时间筛选。
- 支持查看、编辑和删除；删除必须填写原因。
- 设备型号、所属经销商和质保到期日由设备及质保规则自动解析。
- 详情包含绑定设备、质保信息和售后记录。
- 质保临期和过期使用风险状态展示。

### 7.7 设备与库存

#### 7.7.1 设备管理

- SN 使用精确查询，并支持型号、国家、销售地区、激活和绑定状态筛选。
- 单条录入仅填写 SN、设备型号和销售地区。
- 系统自动生成国家、初始固件 `v1.0.0`、未激活、未绑定和离线状态。
- Excel/CSV 导入要求列名完整、SN 唯一、型号有效、销售地区非空；整批校验失败时不写入部分数据。
- 修改销售地区只允许修改国家、地区和原因。
- 强制解绑将原 SN 归档为 `原SN-1`，解除用户关系并写归属历史。
- 远程启停仅平台管理员可执行；结果写入设备命令记录并明确标记为静态模拟。
- 详情展示归属历史、固件历史和售后记录。

#### 7.7.2 仓库设备

- 仓库区展示真实在库设备，一台 SN 对应一条库存设备记录。
- 单条入库由平台管理员录入真实 SN；批量入库由 Excel/CSV 提供每台设备的 SN。
- 出库只能选择平台在库设备和有效接收经销商。
- 调货只能选择当前角色有权操作的设备和合法目标经销商。
- 出库或调货完成后，同一事务更新设备库存状态、当前归属、仓库记录、库存流水、归属历史、通知和日志。
- 调货按配置审批链逐级处理，只有当前审批账号可以操作。
- 归属查询要求输入完整 SN，展示当前归属和完整变更历史。

#### 7.7.3 OTA 管理

- 固件版本号格式为 `1.0.0` 或 `v1.0.0`。
- 新增时选择适用设备类型、固件文件、版本说明、强制更新和发布状态。
- 固件文件仅保存文件名、大小、类型和校验结果，不持久化大体积二进制。
- 支持草稿、发布和撤回；操作写发布记录和审计日志。
- 真实设备推送属于外部能力，Demo 只模拟发布状态。

### 7.8 工单与售后服务

#### 7.8.1 故障报修

- 报修由 App 提交，后台不提供新增入口。
- 支持单号或账号、故障分类、状态和提交时间筛选。
- 状态流为“待处理 -> 处理中 -> 已完成”。
- 待处理可分配给有效且有权限的经销商；处理中可回复和完成。
- 分配、回复和完成同步流程记录、通知、待办和日志。

#### 7.8.2 客服留言

- 留言由 App 提交，后台不提供新增入口。
- 支持账号、回复状态和提交时间筛选。
- 待回复留言可以直接回复、转发经销商或升级总部。
- 回复后状态变为已回复；转发和升级同步归属、通知和流转记录。

#### 7.8.3 投诉管理

- 投诉由 App 提交，后台不提供新增入口。
- 支持单号或账号、投诉类型、状态和时间筛选。
- 状态流为“待处理 -> 处理中 -> 已完成”。
- 分配对象必须是有效账号且在当前组织范围内。
- 详情包含投诉信息、处理过程、回复记录和操作日志。

### 7.9 物料、物流与售后履约

#### 7.9.1 物料申请

- 只有经销商账号可以发起申请，申请经销商由当前会话自动生成。
- 物料只能从有效且库存大于 0 的物料中选择，数量必须为正整数。
- 设备只能从当前数据范围内选择。
- 系统按设备型号、设备归属经销商、激活日期和有效质保规则计算质保结果。
- 未找到设备、设备未激活或未配置规则时不得显示为“质保有效”。
- 申请按配置的审批人员逐级处理；只有当前审批账号可以通过或拒绝。
- 末级通过后进入待发货；拒绝后终止后续节点。
- 发货只能选择已启用快递公司，物流单号必须唯一。
- 发货时同一事务扣减物料库存，创建物流记录和物料发放记录。

设备采购作为同一页面内的独立申请类型：

- 只有经销商账号可以发起，采购申请单号、申请经销商、申请时间和审批状态由系统生成。
- 申请人选择采购设备型号并填写数量、预算单价和用途，预算总费用由系统自动计算。
- 设备采购复用物料申请的分级审批链；末级通过后进入“待登记费用”，不进入物料发货流程。
- 平台或具有费用登记权限的账号记录成交单价、实付总金额、付款方式、付款凭证/流水号、付款日期和备注。
- 支付在系统外完成，后台不创建支付订单、不调用支付接口，仅保存费用记录、通知和操作日志。
- 设备采购不得扣减物料库存，也不得创建物料发放记录或物流记录。

#### 7.9.2 物料与库存

- 支持物料新增、编辑和删除。
- 字段包含物料编号、名称、适用设备、采购价、库存数量和状态。
- 采购价属于敏感业务字段，按角色权限控制展示。
- 库存不得为负；被业务引用的物料删除策略由后续后端实现确认。

#### 7.9.3 物料发放记录

- 默认只读，展示物料、发放对象、发放时间、更换时间和履约状态。
- 发放记录至少支持售后物料申请来源。
- 目标需求还应支持销售订单发放和公司主动向经销商发放，并记录来源类型和来源单号。
- 状态为运输中、已领取、已更换；状态变化保留时间和日志。

#### 7.9.4 物流配置

- 支持快递公司、快递100编码、API Key 和启用状态维护。
- API Key 保存后只展示末四位。
- 物料发货只能选择已启用快递公司。
- 测试查询只生成外部调用日志，不修改正式配置、物流、库存或履约记录。

#### 7.9.5 换 SN

- 创建和执行时均校验原 SN 在当前数据范围内且新 SN 唯一。
- 输入原设备 SN 后，系统自动带出原设备名称、型号和类型。
- 新设备需记录新 SN、设备名称、设备型号和设备类型；型号从标准设备目录选择，类型由系统自动生成。
- 新设备名称允许按实际安装位置或用途填写，型号与类型不能自由输入。
- 执行后原设备 SN 追加 `-1` 并解除绑定。
- 新 SN 使用申请中记录的设备名称、型号和类型，并继承地区、固件、激活日期、用户绑定和经销商归属。
- 项目和航点中的原 SN 同步更新为新 SN。
- 生成包含设备名称、型号、类型的新设备记录、归属历史、流程记录、通知和日志。

#### 7.9.6 售后转移

- 当前设备归属经销商或总部账号均可发起，系统根据 SN 自动确定原经销商，不允许人工篡改。
- 经销商发起时，目标经销商只能选择合法上级或同级有效经销商；总部发起时可选择当前数据域内任一正常且非原归属经销商。
- 发起时记录发起账号、角色、时间、转移原因及是否涉及费用。涉及费用时必须记录预计费用、费用承担方和费用说明。
- 第一节点固定为目标经销商确认。只有目标经销商当前确认账号可接收或拒绝，确认前不得变更设备归属。
- 不涉及费用时，目标方确认后直接完成；涉及费用时进入总部费用审批，设备归属继续保持不变。
- 总部费用审批必须登记实际费用、线下付款方式、付款凭证或流水号、付款日期和审批意见；支付不在本系统内执行。
- 总部通过费用审批后才更新设备经销商关系、未完成售后记录归属和归属历史，并生成费用记录、通知与操作日志；任一节点拒绝均终止流程且不改变归属。
- 页面状态为待接收方确认、待总部费用审批、已完成、已拒绝。

#### 7.9.7 质保规则

- 经销商按自身组织和设备类型设置免人工费月数、物料质保月数和启用状态。
- 同一经销商和同一设备类型只能有一条规则。
- 平台管理员可查看全部规则，但不代替经销商新增或编辑。
- 质保计算以设备激活日期为起点，并匹配设备当前归属经销商。

#### 7.9.8 审批流程

- 审批层级支持“二级 -> 一级 -> 平台”“一级 -> 平台”“平台直接审核”。
- 每一级分别保存有效账号 ID，不保存自由文本姓名。
- 审批流程以业务菜单为配置单元，当前支持物料申请、仓库设备（调货审批）、售后转移（费用审批）三类菜单，各菜单独立配置层级与审批账号。
- 同一菜单最多允许一条启用流程；新增或启用重复流程时必须拒绝并提示先停用原流程。
- 物料申请和库存调货发起时读取对应菜单的启用流程；售后转移固定先由目标经销商确认，涉及费用时再追加“售后转移（费用审批）”菜单配置的审批节点。
- 业务发起时将菜单键、流程 ID 和审批节点复制到审批实例。进行中的业务使用该快照，后续修改流程配置只影响新发起业务。

### 7.10 交易与内容

#### 7.10.1 支付订单

- 订单数据只读，支持订单号或用户账号、渠道、状态和支付时间筛选。
- 展示订单号、用户、服务项目、渠道、金额、支付时间和状态。
- 状态包括待支付、支付成功、支付失败和已退款。
- 支付状态由稳定演示数据提供，不调用真实支付网关。

#### 7.10.2 支付配置

- 固定支持微信支付、支付宝、PayPal、Apple Pay、Google Pay 五种方式，不允许新增任意支付类型。
- 每个渠道可独立启停。
- 每个渠道分别维护商户号、密钥、结算币种和说明。
- 密钥只保存脱敏演示值，不保存或展示真实生产密钥。

#### 7.10.3 Banner 管理

- 支持图片、名称、跳转链接、排序和状态的新增、编辑、启停与删除。
- 图片支持 PNG/JPG/WebP，浏览器端校验并持久化预览。
- 删除必须二次确认并填写原因。
- 当前 V3.2 基线使用跳转链接文本；APP 是否消费该配置不在本期后台范围。

### 7.11 系统管理

#### 7.11.1 管理员账号

- 支持平台和经销商管理员新增、编辑、启禁用、锁定状态查询和密码重置。
- 登录账号唯一，长度 4-20 位；初始密码 6-20 位。
- 新增账号关联角色和归属组织，并立即影响实际登录。
- 重置密码后临时密码为 `Reset123!`，下次登录必须修改。

#### 7.11.2 角色权限

- 角色包含名称、数据范围、说明、状态和权限集合。
- 数据范围为全部、本级及下级、仅本组织。
- 权限标识细化到菜单和动作，例如 `devices:view`、`devices:remote`、`materials:ship`。
- 列表导出使用独立的 `模块:export` 权限，可与查看、编辑和审批权限分别配置。
- 保存后刷新当前会话；当前账号失去页面权限时跳转工作台或 403。

#### 7.11.3 操作日志

- 记录登录、退出、增删改、审批、分配、回复和高风险操作。
- 字段包含操作账号、时间、类型、内容、来源 IP、结果和关联对象。
- 日志只读，不能编辑或删除。
- 支持账号、时间和操作类型筛选以及导出。

### 7.13 核心状态机

| 业务 | 合法状态流 |
| --- | --- |
| 账号 | 正常 <-> 禁用；密码错误累计后锁定；重置后首次改密 |
| 报修/投诉 | 待处理 -> 处理中 -> 已完成 |
| 客服留言 | 未回复 -> 已转发/总部处理 -> 已回复 |

| 设备采购申请 | 待审批 -> 已审批/待登记费用 -> 已完成；任一审批节点可转已拒绝 |
| 仓库出库 | 待处理 -> 已完成或已拒绝 |
| 库存调货 | 待审批 -> 下一节点 -> 已完成或已拒绝 |
| OTA | 草稿 -> 已发布 -> 已撤回；撤回版本可重新发布 |

| 售后转移 | 待接收方确认 -> 无费用时已完成；有费用时待总部费用审批 -> 已完成或已拒绝 |

### 7.14 跨模块数据流

#### 7.14.1 设备生命周期

1. 平台录入或导入真实 SN，设备初始为未激活、未绑定、离线。
2. 设备入库生成仓库记录和库存流水。
3. 出库或调货更新设备归属和归属历史。
4. 用户绑定后，用户详情和工作台绑定数量实时变化。
5. 项目引用设备并读取型号、经销商和质保信息。
6. OTA、报修、投诉、换 SN 和售后转移都通过 SN 关联该设备。

#### 7.14.2 物料履约

1. 经销商选择设备和物料发起申请。
2. 系统校验设备归属、激活日期和质保规则。
3. 审批实例按当前流程生成节点。
4. 每个节点仅当前审批账号处理。
5. 末级通过后选择启用快递公司并发货。
6. 发货事务扣减库存，创建物流和发放记录。
7. 工作台待办、通知和操作日志同步更新。

#### 7.14.3 权限变更

1. 平台修改角色权限或管理员状态。
2. 数据库同步账号与角色关系。
3. 当前会话刷新权限。
4. 菜单、路由和按钮立即变化。
5. Service 再次校验，拒绝绕过页面的越权调用。

### 7.15 数据、接口与持久化

#### 7.15.1 核心实体

| 实体组 | 主要实体 |
| --- | --- |
| 身份权限 | auth-accounts、user-auth-accounts、admins、roles、dealers |
| 客户设备 | users、devices、projects、waypoints、ownership-history、firmware-history |
| 仓储 | warehouse、stock-movements |
| 售后 | repairs、messages、complaints、replies、workflow-events |
| 物料履约 | materials、material-catalog、approval-flow、approval-instances、approval-steps、logistics-records、issuance |
| 外部模拟 | device-commands、external-call-logs、notifications |
| 交易内容 | payments、payment-settings、banners |
| 审计 | logs |

#### 7.15.2 接口结构

```ts
type ApiResult<T> = { code: number; msg: string; data: T }
type TableDataInfo<T> = { code: number; msg: string; rows: T[]; total: number }
```

列表查询统一使用 `pageNum`、`pageSize`、`orderByColumn`、`isAsc`、`tab` 和业务筛选字段。页面只能调用 Service；Service 负责权限、数据范围、字段校验、事务联动、通知和日志。

#### 7.15.3 本地事务

跨表操作使用“校验 -> 复制当前数据 -> 联动修改 -> 统一提交”。任何步骤失败时恢复操作前快照，不允许只写入一部分记录。

#### 7.15.4 数据恢复

平台账号菜单提供“恢复示例数据”。恢复前二次确认，恢复后重建 v11 种子数据并刷新页面。该操作会清除当前所有本地演示修改。

### 7.17 当前实现差异与待关闭问题

| 编号 | 当前差异 | 目标处理 | 验收要求 |
| --- | --- | --- | --- |
| GAP-001 | 质保规则当前位于售后配置，V3.2 表格结构将相关字段归在支付订单区域 | 产品确认最终信息架构；不得自行增加订单与质保规则逐单外键 | 菜单和文档归属一致，质保计算逻辑不受影响 |
| GAP-002 | 无激活日期或无匹配质保规则时，物料申请可能被标记为质保有效 | 增加未激活、未配置规则、无法校验状态 | 三种异常均不能显示为质保有效 |
| GAP-004 | 发放记录主要由售后物料申请发货生成 | 增加来源类型和来源单号，支持销售订单及公司主动发放 | 三种来源可查询且数据关联完整 |
| GAP-005 | 商户参数为通用记录，不一定逐支付渠道配置 | 五个支付渠道分别维护商户参数 | 每个渠道可独立编辑且密钥脱敏 |
| GAP-006 | “保持登录 7 天”控件固定勾选，没有会话行为 | 删除该控件，或经确认后实现真实偏好 | 页面不出现无效控件 |
| GAP-007 | 全局搜索提示支持设备、用户、工单和订单，实际仅跳设备页 | 实现统一搜索结果，或收窄为设备 SN 搜索 | 提示文字与实际行为一致 |
| GAP-008 | 当前需求覆盖报告以登记状态为主，不能替代行为验收 | 将每条关键需求关联可执行断言 | 不存在只有“状态=通过”而没有行为证据的关键需求 |

### 7.18 产品增补：跨菜单关联跳转

本节是客户确认的操作效率增补，不修改 V3.2 原文功能定义，也不产生新的业务数据关系。只有数据库中存在稳定关联、当前账号可访问目标菜单且关联结果大于 0 时才显示入口。

#### 7.18.1 跳转与筛选协议

- 高频目标在列表操作区和详情摘要区显示直接按钮，其余目标收纳在“关联数据”菜单。
- 关联条件使用 `rel_userId`、`rel_deviceSN`、`rel_ownerId` 等稳定 ID 或 SN 写入 URL；账号、手机号和邮箱不得写入 URL。
- 页面人工筛选使用 `f_字段名`，同一关联字段的多个值按 OR 处理，不同关联字段之间按 AND 处理。
- 目标页显示来源记录、关联含义和匹配数量；“重置”只清除人工筛选，“清除关联条件”才解除关联范围。
- 跳转使用当前标签页并记录来源完整 URL。返回后恢复来源页的 Tab、筛选、分页、排序和详情 Tab。
- 目标数据被删除、移出数据域或权限变化为不可见时，显示关联数据变化提示，不泄露不可见记录数量。

#### 7.18.2 核心关系

| 来源 | 高频目标 | 其他关联目标 |
| --- | --- | --- |
| 用户 | 绑定设备 | 报修、留言、投诉、支付订单 |
| 经销商 | 管理设备 | 项目、管理员、工单、投诉、物料申请 |
| 项目 | 绑定设备 | 经销商、质保规则、售后记录 |
| 设备 | 绑定用户；未绑定时为项目 | 经销商、仓库归属、OTA、报修、投诉、物料申请 |
| 仓储单据 | 涉及设备 | 来源/目标经销商、设备归属历史 |
| 报修/留言/投诉 | 设备或用户 | 处理经销商 |
| 物料申请 | 设备 | 物料、经销商、质保规则、发放记录 |
| 换 SN/售后转移 | 当前设备 | 项目、归属历史、原/目标经销商 |
| 管理员/角色/日志 | 角色或账号 | 经销商、账号日志、原业务对象 |

#### 7.18.3 数据约束

- v9 为设备、报修、留言、投诉和支付记录补齐 `userId`，发放记录补齐 `deviceSN`，日志补齐 `subjectModule` 与 `operatorAccountId`。
- 解绑清空设备 `userId`；换 SN 将用户关系迁移到新设备；物料发货将申请设备 SN 写入发放记录；审计日志自动记录原业务模块。
- 页面通过批量 `relatedNavigation(moduleKey, recordIds)` 获取入口与当前可见数量，禁止逐行绕过 Service 查询全量数据。

## 附录 A：开发约束

- 不允许页面直接访问 `localStorage` 业务记录。
- 不允许使用自由文本代替经销商、账号、设备、快递或审批人关联。
- 不允许为只读审计数据增加任意删除入口。
- 不允许通过新增展示字段维护可实时计算的统计数量。
- 不允许绕过 Service 权限和状态校验。
- 不允许随机制造接口失败，演示必须稳定可重复。

## 附录 B：测试数据原则

- 每个用户、设备、项目、经销商、质保、物料申请和发放记录必须能够追溯到真实关联实体。
- 测试新增记录使用唯一业务编号和 SN，完成后按允许的业务方式清理或恢复示例数据。
- 测试物流查询只检查外部调用日志，不得改变正式履约数据。
- 自动化测试不得依赖固定行号，应通过业务编号或关系字段定位记录。
- 覆盖矩阵只能作为索引，最终状态以行为断言为准。
