# 鲨鱼妹妹后台管理系统操作手册与业务逻辑说明

版本：V1.1  
更新日期：2026-09-20  
适用系统：鲨鱼妹妹运营管理后台（纯前端演示版）

## 1. 手册用途

本手册用于项目演示、内部培训、客户讲解和验收。内容覆盖登录、菜单操作、角色权限、设备与产品、仓储与采购、售后、扫码支付、审批、区域异常、内容运营及系统管理。

当前系统是可交互的静态 Demo。业务数据保存在浏览器 `localStorage` 中，新增、编辑、审批、流转、库存扣减、日志等操作会真实改变当前浏览器中的演示数据；硬件控制、真实定位、真实支付、快递查询、消息推送和后端接口仍为 Mock 或预留边界。

## 2. 演示账号与权限

## 3. 系统整体逻辑

### 3.1 数据和权限

1. 平台管理员查看全部授权数据；经销商只能查看所属数据范围。
2. 角色权限同时控制菜单、路由和按钮，不能仅靠隐藏菜单规避越权。
3. 国内与海外是两个数据域，平台管理员切换后，列表、统计、支付配置和 Banner 等内容随数据域变化。
4. 业务操作会写入操作日志；高风险操作必须填写原因。
5. 列表中的详情、关联数据、审批节点、物流、付款和历史记录均来自同一组业务实体，不维护互相矛盾的展示副本。

### 3.2 通用页面操作

- 页签：按业务状态快速切换，例如“待处理”“处理中”“已完成”。
- 查询：填写筛选条件后点击“查询”。不同筛选字段之间是 AND 关系，关键词可匹配配置的多个字段。
- 重置：清空筛选、排序和页码，恢复当前页签默认列表。
- 排序：点击表头排序按钮，在升序、降序和默认顺序间切换。
- 刷新：重新读取当前浏览器数据库中的最新数据。
- 导出：只导出当前角色、数据域、页签和筛选条件下可见的数据，并记录审计日志。
- 查看详情：打开右侧详情抽屉；详情中的页签用于查看关联数据和历史。
- 新增/编辑：必填项未完成时不能保存；点击取消或关闭按钮不写入数据。
- 高风险操作：禁用、解绑、删除、驳回等操作会先显示影响说明，再要求填写原因。

### 3.3 左侧导航业务顺序

左侧导航按正式业务顺序排列：工作台 -> 客户与渠道 -> 设备与产品 -> 仓储与采购 -> 服务与售后 -> 财务与支付 -> 内容运营 -> 系统管理。产品采购、售后物料申请和物料库存分别使用独立菜单；系统管理固定放在最后。

## 4. 首页讲解

首页展示互不重复的实时指标：注册用户总数、新增用户数量、设备总数、新增设备数量、待处理报修、待处理留言和经销商总数。

“运营待办”按当前账号计算：待我审批、待财务核实、待仓库发货、跨区激活异常。左侧“审批中心”同时显示待审批数字提醒。首页数字来自业务实体实时计算，不单独维护一套容易失真的统计数据。

建议讲解顺序：先说明“新增设备数量”已经补充，再说明待办数字不会与总量统计重复，最后从快捷入口进入审批中心或故障报修。

## 5. 客户与渠道

### 5.1 用户管理

用于查看 App 注册用户、注册方式、账号状态、绑定设备、服务器航点和最近活跃时间。后台不新增普通用户。

可执行：查看详情、查看绑定设备、查看航点数据、禁用/启用、重置默认密码、强制解绑关联设备。进入详情的“航点数据”页签，可查看当前用户已上传到服务器的航点编号、名称、来源设备 SN、位置、坐标、上传时间和同步状态；数据按用户 ID 关联，本地未上传航点不会显示。账号和联系方式默认脱敏。重置密码后，用户下次登录必须修改密码。

### 5.2 经销商管理

用于维护一级/二级经销商、上级关系、负责地区、默认质保年限和账号状态。

负责地区必须从系统区域字典选择，不能自由填写。新增一级经销商时不显示上级经销商；新增二级经销商时必须选择正常状态的一级经销商作为上级。默认整机质保期按经销商维度维护，实际质保再结合设备当前归属经销商、产品/型号、市场、起算点和规则生效日期计算。经销商禁用或密码重置会同步影响登录实体。

### 5.3 安装管理

原“安装项目”已统一命名为“安装管理”。用于维护船名、设备 SN、设备类型、设备型号、船东、出厂地区、实际安装地区、经销商和质保到期日。

选择设备 SN 后，设备名称、类型、型号和规格由设备主档带出，避免把产品编号、产品名称、设备型号混为同一字段。编辑会保留项目变更历史。

### 5.4 安装跨区审核

当设备出厂地区与实际安装地区不一致时生成审核单。审核通过后安装关系继续生效；拒绝时必须填写原因。临时运行状态仅用于 Demo 表达，不代表真实硬件已被控制。

### 5.5 跨区域激活异常

展示设备销售/归属区域、用户授权后上报的发生/使用区域、定位来源和发生时间。处理时选择“确认跨区使用”“定位误差”或“已调整销售区域”，并填写说明。

系统只展示 App 在用户授权定位后上报的 Mock 地区，不会在用户拒绝定位时伪造位置，也不表示真实 GPS 接口已接入。

## 6. 设备与产品

### 6.1 设备管理

保留后台设备录入和批量导入能力。设备字段明确区分：

- 设备 SN：设备唯一序列号。
- 设备名称：具体设备显示名称。
- 设备类型：如制冷设备、水处理设备。
- 设备型号：如 `CI-02`、`SW-04`。
- 产品规格：从产品与型号主档带出。
- 销售地区：设备的销售/归属区域。
- 最近一次使用地区：用户授权后由 App 上报的最近区域。

强制解绑会保留原设备归属历史；远程禁用/启用在纯前端环境只生成可追踪的模拟指令，离线设备只登记为待联网下发，不宣称设备已响应。

### 6.2 产品与型号

维护产品编号、产品名称、设备类型、设备型号、规格和参考价格。设备录入、安装和采购通过此主档选择产品，避免各页面自由填写造成字段不一致。

### 6.3 OTA 管理

维护固件版本、适用产品、设备类型、设备型号、版本说明、强制更新标记和发布状态。发布、撤回和回滚均为可审计的静态模拟，不会真实向设备下发固件。

## 7. 仓储与采购

### 7.1 产品采购

产品采购已从售后物料申请中独立出来，原“采购发货”入口合并到产品采购的“待仓库发货”页签。

完整流程：经销商选择产品和数量 -> 销售确认 -> 研发确认 -> 导入生产 -> 财务核实付款 -> 仓库决定是否放行 -> 仓库选择设备并发货 -> 经销商确认收货。

“全部采购、待采购审批、待导入生产、待财务核实、待仓库发货、待确认收货、已完成、已拒绝”页签分别对应固定业务节点。采购明细、审批记录、分次付款、发货照片、物流单号和收货信息保存在同一采购单详情中；库存只在实际发货时扣减。

### 7.2 仓库 / 仓位管理

“仓库管理”和“仓位管理”已合并为一个菜单。仓库主档在列表维护，详情中的“仓位”页签查看该仓库下的仓位。仓库和仓位支持新增、编辑和停用，不提供物理删除，避免破坏历史库存关系。

### 7.3 仓库设备

包含仓库区、设备出库、库存调货和归属查询。

- 设备入库：单台录入或批量导入 SN，SN 必须唯一。
- 设备出库：确认出库后同步库存状态和归属历史。
- 库存调货：发起后进入审批，审批通过再变更目标归属。
- 归属查询：查看设备当前和历史归属。

### 7.4 物料与库存

物料主档独立于产品主档，维护物料编号、名称、适用设备、采购价、库存和状态。售后物料发货时从这里校验并扣减库存。

## 8. 服务与售后

### 8.1 故障报修

报修由 App 提交，后台执行“待处理 -> 分配处理 -> 处理中 -> 回复用户 -> 标记完成”。完成后可生成维修支付订单，账单可包含人工费、物料费和调整金额。

### 8.2 客服留言与投诉管理

客服留言支持回复、转发经销商和转回总部；投诉支持分配、回复、转回总部和完成。每次流转都会保存处理人、原因、回复内容、状态和时间。

### 8.3 物料采购

物料采购菜单只处理售后物料申请，不再混入产品采购单据。

售后物料流程：经销商申请 -> 配置的审批节点 -> 平台审核 -> 物料发货 -> 物流记录 -> 确认收货 -> 登记更换 -> 关闭原申请。

### 8.4 物料发放记录

物料发放记录由售后物料发货动作自动生成，不允许随意新增或编辑。

签收后点击“登记更换”，选择关联维修工单并登记旧件编号、新件编号和原因；完成后同步关闭来源物料申请。

### 8.5 审批中心与审批流程

审批中心聚合当前账号待处理的物料采购、调货和售后转移审批。列表展示业务单号、当前节点和当前处理人；通过或拒绝会同步原业务单。

审批流程按业务菜单分别配置审核人员，只影响配置保存后新发起的业务。已发起实例保留自己的审批快照，防止中途修改流程改变历史业务。

### 8.6 物流、换 SN、售后转移和质保

- 物流配置：维护快递公司和脱敏接口参数；“测试查询”只生成静态物流轨迹和调用日志。
- 换 SN：确认后原 SN 归档，新设备接续用户、项目和经销商关系。
- 售后转移：目标经销商确认；涉及费用时再由总部审批和登记线下凭证。
- 质保规则：经销商按产品和市场维护；平台可查看但不替经销商随意修改。

## 9. 支付业务

### 9.1 支付配置

支付配置只维护“供应商收款码”。新增时选择或录入供应商、填写收款户名并上传 PNG/JPG/WebP 二维码图片，单张不超过 2 MB。

系统不再提供微信支付、支付宝支付、商户号、AppID、密钥或支付回调配置。当前二维码是普通静态收款二维码，不具备自动识别订单和金额的能力。

### 9.2 订单与付款绑定

1. 用户从具体订单进入扫码支付，页面展示该订单编号、应付金额和对应供应商二维码。
2. 用户扫码后自行输入金额并完成支付。
3. 用户上传付款截图，截图随当前订单提交。
4. 支付订单进入“待财务核实”。
5. 财务打开当前订单，录入本次核实金额、付款截图、支付凭证号、付款日期和核实说明。
6. 系统把本次核实记录绑定到当前订单，并累加已付金额、减少待付金额、增加付款次数。
7. 未付清时订单继续待处理；累计达到应付金额后变为“已核实”。

一个订单可以多次付款。每次付款都是独立记录，不能覆盖上一笔。采购单即使部分付款，是否允许进入仓库处理也由财务明确选择，不能仅根据“是否付清”自动决定。

## 10. 财务与支付、内容运营

- 支付订单：只读查看订单来源、应付、已核实、待付、付款次数和核实记录；财务核实是唯一修改入口。
- Banner 管理：维护图片、名称、跳转标识、适用用户、排序和状态。
- 常见问题 PDF：维护产品资料 PDF、版本、排序、文件状态和发布状态。
- 客服信息：维护适用用户、客服电话、邮箱和服务时间。

## 11. 系统管理

- APP 启动页：配置短时品牌启动页和首次安装引导页；两类配置互相独立。
- 客户端版本：维护 iOS/Android 版本、适用范围、发布时间和发布状态。
- 管理员账号：新增、编辑、禁用和重置密码会真实影响本地登录。
- 角色权限：配置菜单、查看、新增、编辑、操作和导出权限，以及全部/本级及下级/本组织数据范围。
- 操作日志：只读查看业务操作、登录和高风险操作，可按当前筛选导出。

## 12. 推荐演示讲解路线

1. 使用平台管理员登录，说明角色、数据域和审计机制。
2. 在首页展示新增设备数量和四类互不重复的运营待办。
3. 进入设备管理，解释设备 SN、名称、类型、型号、销售地区和最近使用地区的区别。
4. 进入产品采购，按节点讲解审批、生产、分次付款、仓库发货和收货闭环。
5. 进入“仓库 / 仓位管理”，展示两个原菜单已经合并，以及详情中的仓位页签。
6. 进入物料采购，说明其只承接售后物料申请，并演示物料发放与库存联动。
7. 进入跨区域激活异常，说明“用户授权上报 -> 后台核实 -> 留痕”的逻辑。
8. 进入支付配置，强调按供应商配置二维码，系统没有微信/支付宝商户参数。
9. 进入支付订单，讲解截图人工核实和一个订单多次付款。
10. 进入审批中心，展示菜单数字提醒和原业务单同步。
11. 最后打开操作日志，说明每个关键动作都可追溯。

## 13. Mock 与真实系统边界

当前已实现：页面交互、角色权限、数据域、CRUD、状态流转、审批快照、库存联动、付款记录、关联详情、导出和操作日志。

当前未接真实能力：后端数据库、设备控制、GPS/蓝牙、第三方海图、微信/支付宝/银行支付、二维码自动订单匹配、快递100、ERP、推送、CDN 和服务器部署。页面中出现的这些结果均为有明确说明的 Mock，不应在客户讲解中描述为已上线真实接口。

## 14. 演示数据与故障处理

- 页面数据异常时先点击“刷新”，再检查当前数据域和页签。
- 菜单不可见时检查角色权限，不要直接修改路由规避权限。
- 首次登录被拦截时先完成密码修改。
- 演示数据需要恢复时，使用项目提供的数据重置机制；清除浏览器站点数据也会清除当前浏览器中的演示业务记录。
- 部署到新域名或新路径后，浏览器会使用新的站点存储，旧域名下的 `localStorage` 数据不会自动迁移。
