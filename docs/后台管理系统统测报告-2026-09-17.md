## 5. 核心流程结果

### 5.1 采购履约

经销商发起 -> 销售确认 -> 研发确认 -> 导入生产 -> 财务核实 -> 仓库发货 -> 物流 -> 确认收货，状态、审批节点、库存、设备归属、付款记录和日志均同步。测试通过。

### 5.2 多次付款

同一订单第一笔付款后保留待付余额并增加付款次数；第二笔累计达到应付金额后变为已核实。每笔付款截图和凭证独立保存。测试通过。

### 5.3 售后物料闭环

申请 -> 审批 -> 发货 -> 物料发放记录 -> 确认收货 -> 登记更换 -> 关闭原申请。测试通过。

### 5.4 区域异常

设备销售地区与 App 授权上报地区分开存储；跨区记录关联真实设备，后台处理后写入处理人、结论和审计记录。测试通过。

### 5.5 权限与审计

平台、一级和二级经销商菜单及数据范围不同；未授权路由返回 403；关键操作生成日志；只读模块拒绝任意写入。测试通过。

## 6. 未接真实接口的边界

以下能力不属于本轮纯前端交付：真实后端数据库、设备控制、GPS/蓝牙、第三方海图、微信/支付宝/银行支付、二维码自动识别订单和金额、快递100、ERP、消息推送、CDN 和服务器基础设施。

这些页面可以演示完整业务逻辑，但上线前必须由后端、硬件或第三方接口替换 Mock 服务。尤其支付环节当前依赖“订单内上传截图 + 财务人工核实”，不能对外说明为自动到账或自动对账。

## 7. 回归建议

接入真实后端后，应重点回归：并发库存、重复 SN、支付幂等、分次付款累计精度、审批并发、文件存储、数据域隔离、接口鉴权、日志不可篡改和跨域部署路径。
